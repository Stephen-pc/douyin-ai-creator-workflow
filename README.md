# 抖音 AI 赛道创作工作流（不出镜 · 单人）

一份给 AI 工具 / AI 编程 / 提示词赛道**不出镜博主**的操作手册。不是提示词合集，是一套带路由和诊断标准的流程文档。

覆盖：观众分层 → 定位 → 选题 → 脚本 → 批量生产 → 发布 → 单变量复盘 → 回选题。
默认两条约束：**不出镜**、**涨粉和引流同时要**。

核心主张只有一句：AI 赛道最强的信任源是"看着它真的跑起来了"。所以形态首选录屏，脚本首选结果先行。

---

## 这是什么

- 一个 Agent Skill（`SKILL.md`），支持 WorkBuddy / Claude Code 等能读 `SKILL.md` 的宿主
- 也是一份**纯人类可读**的手册：不需要任何宿主，直接打开 `SKILL.md` 就能照着做
- 每个阶段都有明确的**交付物**：选题要出选题卡、脚本要出配音稿和分镜表、复盘要出"下一条只改什么"

## 不是什么

- 不承诺收益。没有"三天起号""月入过万"这类内容，也不给这类话术
- 不含灰产手法。搬运、洗稿、刷量、破解付费墙、绕风控、伪造身份，一律没有
- 不是通用抖音运营教程。只覆盖 AI 赛道、不出镜、单人作业这三个前提下的做法

## 安装

### WorkBuddy

把整个目录放到用户级 skills 目录：

```
~/.workbuddy/skills/douyin-ai-creator-workflow/     # macOS / Linux
C:\Users\<你的用户名>\.workbuddy\skills\douyin-ai-creator-workflow\   # Windows
```

目录名要和 frontmatter 里的 `name` 一致。

### Claude Code / 其他支持 SKILL.md 的宿主

放进对应的 skills 目录即可。两点注意：

1. frontmatter 里的 `agent_created: true` 是 WorkBuddy 专有字段，**其他宿主可以直接删掉**，不影响任何功能。
2. 目录名必须是 `douyin-ai-creator-workflow`，与 `name` 保持一致。

### 纯当文档读

不装。直接读 `SKILL.md`，按里面的表格逐阶段推进。

## 怎么用

装好之后直接说需求，它会自己路由到对应阶段：

| 你说 | 它交付 |
| --- | --- |
| "不知道这周做什么" | 5-10 张选题卡，标出先做的 3 条 |
| "帮我写脚本" | AI/真人配音稿 + 分镜 / 录屏清单 |
| "这条为什么不火" | 单变量诊断 + 下一条只改什么 |
| "粉丝多了但不引流" | 转化链路检查 + 改法 |
| "账号做不起来" | 一句话定位 + 3 个支柱 + 主页检查 |
| "这周做什么" | 7 天选题 / 生产 / 发布表 |

第一次用会问你五个问题（观众层级、证据、配音方式、引流去向、周产能）。这五个答案决定后面所有建议，不答清楚它给的东西就是空的。

## 已知局限

**发布前请先读这一节。这是诚实的边界说明，不是免责套话。**

1. **「复盘」章节的诊断归因是行业通用推理，不是实测数据集。**
   例如"播放卡在几百起不来 → 选题没搜索词"，这只是一种常见解释；也可能是新号权重、封面问题或赛道竞争。
   请用你自己后台的历史中位数校准后再采信。不同品类、不同阶段的账号，同一现象的原因可能完全不同。
2. **未区分账号阶段。** 0-1000 粉和 10 万粉，同一套规则的执行重点不一样（前者该打标签、测钩子；后者才谈转化）。
   当前版本按"已有稳定更新节奏"的中位账号写。新号请自行降低对转化类指标的要求。
3. **未展开抖音的两个流量入口。** 搜索流量（要关键词密度、要长尾词）和推荐流量（要钩子强度、要完播）是两种做法，
   本文只在选题的"搜索词"字段擦到边，没有系统拆解。
4. **易过期。** 具体工具名、模型名、热点类建议的半衰期以周计。真正不变的是方法论：分层、结果先行、单变量复盘、按归属选指标。工具名请自行替换。
5. **不承诺长期维护。** 按需自取，欢迎 fork 后自己演进。

另外，「观众分层」只分了三层，是刻意的：层数再多，选层本身就成了负担，账号主页也更容易散。
